Executive summary

What the evidence supports, where time is best spent, and what still needs review. Prepared 2 November 2026.

BOTTOM LINE

Use a small, rules-first shortlist.
Do not chase headline pools.

The source ledger contains 206 listings, but its age, mixed payout types and broken links make it unsafe as a ready-to-enter list. This view retains all 206 identities and adds 18 separately sourced event records. Twelve event records have both free-entry and cash evidence with a published open or closing window; only a subset fits an agent-assisted workflow.

Recommended order of research

01

Kiroween — clearest named-agent workflow

Official rules require Kiro and evaluate specs, hooks and agent workflows. First prize is $30,000; submission closes 4 December 2026 at 2:00 pm Pacific. The trade-off is a public open-source GitHub repository, a public demo and regional/tool restrictions.

Official rules ↗
02

UGREEN — low initial submission burden, explicit Singapore listing

Round 1 needs a concise PDF and initial skill ZIP, not a demo or NAS runtime. The top cash award is $20,000. Only finalists receive hardware access, and the rules bar an outside person from developing the project or submission materials. Do not assume an external agent is permitted.

Official rules ↗
03

Codegeist / PayPal / NFL Big Data Bowl — investigate tool permission first

These have documented cash awards and no-fee entry clauses, but their AI or technical-assistance language is not blanket coding-agent authorization. Codegeist closes 22 December; PayPal 12 November; NFL Big Data Bowl 6 January. Read ownership, tool-cost and reproducibility rules before building.

Codegeist ↗PayPal ↗NFL rules ↗

Ordering is editorial: explicitness of the agent path, submission requirements and runway. It is not a probability model, hourly-return estimate or financial recommendation.

What was verified

  • The upstream repository’s current commit and the pinned 206-listing snapshot.
  • Every inherited row’s identity, category, unique ID and official-source pointer presence.
  • Field-level quotes for 18 event records, with blanks for unsupported values.
  • Official source reachability is reported separately when the audit artifact is available; HTTP success never verifies an offer.
  • Generated local links, anchors, assets, CSV parity and deterministic builds are tested.

What was not verified

  • Current operational terms for every inherited listing. Unsupported fields remain blank and flagged.
  • Your personal residency, age, tax status, identity or prize eligibility.
  • Actual payout receipt, win probability, expected return or typical earnings.
  • Every external page’s full legal terms. Only cited passages support published cells.
  • Live login, registration or submission-form availability. No contest accounts or entries were created.

Repository irregularities

The repository already contains multiple parallel dashboards and audit supplements. This session preserves them and publishes an isolated view instead of overwriting shared data. Historical coordination claims and some root summary counts are stale; the current root checker is the source for current counts. The upstream repository has no detected license, and its 100_VERIFIED_CONTESTS.md explicitly says it failed verification and must not be used as a source.
