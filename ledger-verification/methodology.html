Methodology and sources

How the data is built

  1. The upstream ledger's assets/data.js was snapshotted unmodified (data/source/ledger-data.js, commit 466f7c1).
  2. Each listing is loaded and checked against a verification record (data/review.json). Official pages were fetched on 2026-11-01.
  3. A value is shown as verified only when an official page confirms it on that date. Otherwise the prize cell is left blank and the row is flagged.
  4. Ledger values are kept, labelled "unverified", in expandable notes only. They never appear in a verified column.
  5. Flags come from this review, plus automatic checks: missing official source, http links, missing rules link, and the presence of promo codes (codes are not published).

Verification status

StatusMeaning
VerifiedAn official page was fetched on 2026-11-01 and the stated value matched.
Partially verifiedAn official page was fetched. Some fields matched; the rest were not confirmed.
Conflict with official pageAn official page contradicts the ledger. The official value is shown.
Broken linkThe ledger link does not show the claimed contest.
UnverifiedNot checked against an official page in this pass. Prize blank.

Limits of this pass

  • 11 of 206 rows were checked. The rest are unverified.
  • Official pages were read with a page fetcher. Logins, eligibility tests and account sign-ups were not done.
  • Pages were read as they stood on 2026-11-01. Contests can change.
  • Rules pages can run to several sections. Where a prize section was not read, the prize is blank.

Reproduce

node ledger-verification/tools/build.mjs then node ledger-verification/tools/check.mjs. Generated pages are committed in ledger-verification/; the workflow .github/workflows/ledger-verification.yml fails if they differ from a fresh build.
